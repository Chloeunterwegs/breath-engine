# Feature Spec: 呼吸引擎 Breath Engine

## 目标
MVP：用户在移动端浏览器打开应用，呼吸/哼唱驱动 AI 支声合唱生成，
配暗色侗锦可视化，零后端零外部依赖。

## MVP 验收线（硬约束，逐条核）
- `python3 -m http.server` 启动，手机浏览器打开即呼吸触发合唱，全程无任何网络请求。
- 纯前端 HTML/CSS/JS + Web Audio + Canvas 2D；零后端、零 API Key、零外部 CDN。
- 首次呼吸 → 声部回应 → 连续呼吸 → ≥4 声部慢半拍进入 → 停止 8s → 逐层退场。
- 无麦克风可切 Demo Mode（模拟呼吸包络）录完整流程。

## User Stories
1. 作为用户，我打开应用后看到沉睡的侗锦纹样与「试一次呼吸」引导，知道下一步做什么。
2. 作为用户，我对着手机呼吸/哼唱，应用实时检测呼吸包络，用五声调式音符回应。
3. 作为用户，我连续呼吸时，多个 AI 声部依次「慢半拍」进入形成支声织体；
   我停止呼吸 8 秒后声部逐层退场。
4. 作为演示者，我在手机上录 3 分钟 Demo：开场引导 → 单次呼吸响应 →
   连续呼吸合唱 → 停止退场。全程无卡顿、无外部服务。

## Acceptance Criteria
- AC1 页面加载 < 1s（本地静态资源），无任何网络请求。
- AC2 麦克风权限被拒时显示非阻塞提示，应用仍可进入演示模式（模拟呼吸包络）。
- AC3 呼吸检测：振幅包络 + 起音检测，事件响应延迟 < 150ms。
- AC4 支声引擎：≥ 4 个 AI 声部，声部 i 相对延迟 i 个呼吸周期「慢半拍」进入；
  音高限定五声调式（宫商角徵羽，可调参）。
- AC5 可视化与音频同步：纹样明灭、声部光斑与音频事件同帧渲染。
- AC6 演示模式：按钮触发模拟呼吸包络，Demo 不依赖真实麦克风也能录。
- AC7 移动端 Safari + Chrome 真机全流程走查通过。
- AC8 Showstopper：打开第一秒即全屏纹样 + 呼吸引导，无介绍页、无登录、无满屏按钮。
- AC9 可打断：声部进入/退场可被随时打断（停止呼吸即退场），有阻尼回弹，非死板动画。

## Out of Scope（本期）
- 真实可穿戴硬件。
- 多人联机、云服务、注册系统。
- 完整 DialKit 调参面板（多滑块实时调参 UI）——MVP 仅 js/config.js + 透视开关接口。
- Machine/Human 双模式对比（算法平均律 vs 慢半拍支声）——「断气→托住」母题已承担戏剧冲突，对比模式是 MVP 后加分项。
- 织锦纹样/音频导出（PNG/WAV）——加分项，不进 T1–T8。
